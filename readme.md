# To Do Inn!

Учебное веб-приложение на HTML, SCSS, vanilla JavaScript, PHP и PostgreSQL.

## Локальный запуск

1. Установите PHP с `pdo_pgsql`, PostgreSQL и Node.js.
2. Создайте локальную базу и пользователя PostgreSQL, затем заполните `.env` по образцу `.env.example`.
3. Создайте таблицу пользователей:

   ```sh
   set -a
   source .env
   set +a
   psql -h 127.0.0.1 -U "$PG_USER" -d "$PG_DATABASE" -f database/schema.sql
   ```

4. Установите frontend-зависимости и соберите приложение:

   ```sh
   npm install
   npm run build
   ```

5. Запустите PHP API и Vite в двух терминалах:

   ```sh
   php -S 127.0.0.1:8000 -t public
   ```

   ```sh
   npm run dev
   ```

   Откройте <http://localhost:5173>. Vite проксирует `/api` на PHP-сервер.

Для разработки SCSS используйте `npm run dev:styles` в третьем терминале. `npm run build` компилирует SCSS через Gulp и собирает production-страницы React через Vite в `dist/`. Каталог `public/` с исходными HTML-оболочками и PHP API при сборке не перезаписывается; для ручного production-развёртывания подготовьте содержимое `dist/` вместе с PHP-файлами приложения.

## Авторизация

Регистрация и вход доступны через JSON API в `public/api/auth.php`. Настройки профиля доступны в `public/api/profile.php`: логин можно менять раз в 24 часа, пароль — после проверки текущего, а аватар JPEG/PNG/WebP размером до 1 МБ хранится в PostgreSQL. Основная и дополнительная почта проверяются на формат и уникальность, но пока не подтверждаются письмом. Пароли хранятся только как хеши; изменения защищены CSRF-токеном.

Для рабочего пространства `database/schema.sql` также создаёт доски, пользовательские флаги и списки. У каждого аккаунта автоматически есть доска «👋 Hello World!». Доски, списки, флаги и задачи сохраняются в PostgreSQL; тип доски и тип аккаунта пока не управляют доступом или совместной работой.

Восстановление пароля пока не реализовано: отправка e-mail и подтверждение владения адресом требуют настройки почтового сервиса. Типы командных и корпоративных аккаунтов пока сохраняются как выбор пользователя, но не включают совместный доступ.

Текущую установку используйте локально. Перед публичным развёртыванием необходимо отдельно настроить HTTPS, ограничить регистрацию/доступ, добавить защиту от перебора паролей и проверить конфигурацию production-сервера.
