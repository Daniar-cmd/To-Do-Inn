# Архитектура To Do Inn

To Do Inn состоит из React-фронтенда, одного ASP.NET Core приложения на .NET 10 и PostgreSQL. Внутри бэкенда код сгруппирован по предметным областям. Caddy раздаёт фронтенд и проксирует HTTP-запросы к Kestrel.

## Репозиторий

| Путь | Назначение |
| --- | --- |
| `frontend/` | HTML-страницы, React/TypeScript и SCSS. Общие компоненты находятся в `frontend/js/ui/`. |
| `backend/Workspace.Api/` | HTTP API, почта, фоновые команды и миграции PostgreSQL. |
| `backend/systemd/` | Описание сервиса API и таймера повторяющихся задач Linux. |
| `backend/Caddyfile.*` | Маршрутизация локального Docker, стенда и production. |
| `public/favicon.svg` | Общая иконка приложения. |
| `dist/` | HTML и ассеты, собранные Vite. |
| `tests/js/` | Тесты React, API-клиента и сборки. |
| `tests/Workspace.Api.LocalSmoke/` | HTTP-приёмка через настоящий ASP.NET Core с временной PostgreSQL и тестовым почтовым транспортом. |

## Модули ASP.NET Core

Все модули собираются в `Workspace.Api.csproj`. Названия пространств имён повторяют вложенность каталогов.

| Каталог в `backend/Workspace.Api/` | Ответственность |
| --- | --- |
| `Hosting/` | Регистрация зависимостей, middleware, конфигурация публичного API и фильтр внутреннего маршрута. |
| `Accounts/Auth/` | Вход, регистрация, восстановление пароля, личные и корпоративные сессии, CSRF. |
| `Accounts/Profile/` | Просмотр и обновление профиля, смена пароля, проверка аватаров. |
| `Organizations/` | Создание и принятие корпоративных приглашений. |
| `Workspaces/` | Чтение и поиск по доскам, списки, флаги, закрепление и общий порядок карточек. |
| `Workspaces/Tasks/` | Создание, изменение, перемещение, удаление и повторение задач. |
| `Workspaces/Notes/` | Заметки и операции над их изображениями. |
| `Infrastructure/Postgres/` и `Migrations/` | Хранилище сессий, проверка готовности, принятие и обновление схемы. SQL миграций включён в сборку. |
| `Infrastructure/Mail/` и `Mail/` | Почтовый транспорт и встроенные шаблоны писем. |

`Program.cs` выбирает HTTP-запуск или эксплуатационную команду. `ApiHosting` настраивает Kestrel, службы, сессии и публичные маршруты. `InternalApiRoutes` хранит состояние проверки одноразовых подписей внутреннего маршрута совместимости, который в production закрыт.

HTTP-обработчики проверяют метод, идентичность, CSRF и ограничения тела запроса в порядке, ожидаемом клиентом. `SessionCsrf` отвечает за выдачу, проверку и сброс токена. `WorkspaceActor` передаёт серверный ID пользователя и версию пароля между маршрутизацией и записью, где версия повторно сверяется под блокировкой PostgreSQL.

Сервисы с зависимостями получают их через встроенный DI ASP.NET Core. `ProfileReader` возвращает типизированную запись профиля для HTTP-чтения и ответа после сохранения. Повторное чтение после записи выполняется внутри той же транзакции. `TaskRecurrenceService` выполняет генерацию повторов для таймера и внутреннего HTTP-маршрута. Он владеет соединением и транзакциями генерации. В сценарии таймера служба берёт блокировку владельца, в сценарии совместимости её удерживает вызывающая сторона. Другие операции рабочего пространства держат параметризованный SQL рядом со сценарием, который определяет транзакцию и блокировки.

При добавлении операции размещайте её в предметном модуле. Выносите I/O и общие сценарии в отдельные классы, когда они разделяют ответственность или используются несколькими точками входа. Сохраняйте код разбора HTTP и форматирования ответа в обработчиках.

## HTTP и пользовательские данные

- В Docker Caddy раздаёт сайт на `localhost:5173` и направляет `/api/*` в Kestrel. При нативном запуске запросы проксирует Vite в `127.0.0.1:8002`.
- ASP.NET Core обслуживает прежние контракты `/api/auth.php`, `/api/profile.php`, `/api/workspace.php` и `/api/notes/{noteId}/image`. Клиент получает CSRF из `GET /api/auth.php` и передаёт его при записи в `X-CSRF-TOKEN`.
- Списки и заметки используют общий порядок карточек. PostgreSQL хранит аватары и изображения заметок. Одна заметка содержит до одного изображения.
- Корпоративные доски доступны принятым участникам через личный аккаунт. Права на управление досками и приглашениями принадлежат владельцу. [Корпоративные аккаунты и роли](corporate-accounts.md).

| Окружение | PostgreSQL |
| --- | --- |
| Локальный Docker | `todo_inn_docker_workspace` в томе `postgres`. Ключи сессий хранятся в томе `session-keys`. |
| Нативный запуск | База из `.env.aspnet.dev`. Пример использует существующую локальную `todo_inn_laravel_dev`. |
| Тесты | Отдельный временный экземпляр PostgreSQL, который запускает `npm run test:local`. |
| Production | Существующая серверная PostgreSQL. |

Схемой управляют явные команды `schema:init`, `schema:baseline` и `schema:migrate`. Baseline хранит метаданные принятой схемы и историю миграций. Секреты, ключи Data Protection и резервные копии хранятся вне репозитория. При переносе базы сохраняйте идентификаторы, хеши паролей, вложения, ограничения и последовательности.

## Сборка и проверки

Gulp компилирует SCSS в `frontend/css/`, Vite собирает HTML и ассеты в `dist/`. Каталог дизайна доступен в Vite development и исключён из production inputs. [Библиотека дизайна](design-system.md).

На VPS Caddy читает `/opt/todo-inn/current/dist` и направляет API в Kestrel на loopback. systemd запускает приложение и команду `tasks:repeat` по таймеру. Развёртывание приложения и применение миграций выполняются отдельно.

```sh
npm run typecheck
npm run test:frontend
npm run build
npm run test:local
```

Последняя команда проверяет сохранность данных при миграции, авторизацию, профиль, приглашения, рабочее пространство и повторяющиеся задачи. Команды локального запуска приведены в README, сценарии перехода и отката — в истории миграции. [README](../readme.md) · [История миграции](csharp-aspnet-migration.md).
