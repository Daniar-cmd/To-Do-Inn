# Библиотека дизайна To Do Inn!

Локальный каталог: [localhost:5173/pages/design-system.html](http://localhost:5173/pages/design-system.html).

Запуск: `npm run dev` и `npm run dev:styles`. Каталог не требует входа или API. Его примеры меняют только локальное состояние React и не записывают данные. Проверяйте обе темы и узкий экран. HTML не включён в production inputs Vite; отдельный CSS каталога компилирует Gulp, но основное приложение его не загружает.

## Обязательный порядок работы с интерфейсом

1. Найти подходящий блок в каталоге и сверить его с рабочим экраном.
2. Переиспользовать компонент, иконку, класс, текст и токены. Не создавать похожий элемент заново.
3. Сохранить обычное состояние, hover, нажатие, выбранное состояние, открытый редактор, disabled и клавиатурный фокус. Проверить обе темы, мобильный режим и reduced motion.
4. Если подходящего варианта нет, объяснить отличие до изменения общего оформления. После изменения общего элемента обновить каталог и эту памятку в той же задаче.
5. Проверить `npm run test:frontend` и `npm run build`. Каталог не заменяет проверку реального экрана.

Эта библиотека фиксирует текущий дизайн, а не разрешает переделывать весь интерфейс. Новые зависимости, router, Storybook и отдельный CSS-фреймворк не нужны.

## Источники

| Что | Источник | Как использовать |
| --- | --- | --- |
| Публичные React-блоки | `frontend/js/ui/index.js` | Импортировать именованный экспорт |
| Иконки | `frontend/js/ui/icons.jsx` | Использовать готовую геометрию, без изменения штрихов |

| Палитры, размеры, время анимаций | `frontend/scss/_variables.scss` | `@use 'variables' as v` |
| Кнопки, карточки, состояния, анимации | `frontend/scss/workspace/` | Переиспользовать существующие классы; `_workspace.scss` подключает эти части по порядку |
| Регистрация и CustomSelect | `frontend/scss/_auth.scss` | Сохранять существующий вариант регистрации |

Общие иконки и часть текстов уже подключены к Workspace и диалогу. Ещё существующие inline SVG и строки не заменяем массово: при работе с конкретным блоком сначала ищем соответствующий элемент в библиотеке. Ответы API и серверная валидация остаются на backend.

## Цвета

`$workspace-light` и `$workspace-dark` задают значения CSS-переменных `--workspace-bg`, `--workspace-surface`, `--workspace-text`, `--workspace-muted`, `--workspace-border`, `--workspace-hover`. В компонентах используем эти семантические переменные, а не новый похожий hex.

`$task-accent` — текущий синий акцент `#3478d4`. Звезда использует `$important-background`, `$important-border`, `$important-text` только при выборе. `$flag-colors` описывает существующие пять цветов флагов.

Не объединять палитру регистрации (`$blue`, `$navy` и т. д.) с workspace без отдельного решения: у них уже есть разные значения.

## Кнопки и состояния

Базовый готовый класс: `.list-option-button`. В панели задач он используется внутри `.task-create-dialog .task-create-toolbar`.

| Состояние | Разметка / поведение |
| --- | --- |
| Обычное | Фон `--workspace-surface`, текст `--workspace-muted` |
| Hover | Тот же общий селектор, что у меню создания списка: `--workspace-hover` и `--workspace-text`; без приподнимания кнопки |
| Выбранный параметр | `.is-selected`, нейтральный фон; без точки в углу |
| Открытый редактор | `aria-expanded="true"`, синяя рамка и фон |
| Важная задача | `.task-create-important-button`, `aria-pressed`; серая до выбора, жёлтая после |
| Дополнительные параметры | `.task-create-more-button`, залитый синий; тот же PlusIcon, поворот 45°, без scale и изменения толщины |
| Недоступное действие | Нативный `disabled` |
| Клавиатурный фокус | Общий `:focus-visible`, не заменять только hover-подсветкой |

```jsx
import { FlagIcon, uiText } from '../ui/index.js';

<button
  type="button"
  className={`list-option-button task-create-property-button${selected ? ' is-selected' : ''}`}
  aria-expanded={open}
  onClick={openEditor}
>
  <FlagIcon color={selectedColor} />
  <span>{uiText.task.flag}</span>
</button>
```

Важно: прямой ребёнок toolbar с `aria-pressed="true"` предназначен для звезды и получает жёлтый стиль. Флаг размещается в `.flag-picker`, дата — в `.list-creator__date`. Сохраняйте структуру существующего блока.

## Иконки

Доступны `PlusIcon`, `StarIcon`, `FlagIcon`, `AnnotationIcon`, `LocationIcon`, `UserIcon`, `SettingsIcon`, `BoardTypeIcon`.

Обычный размер SVG — 17 × 17 px, viewBox — 24 × 24. Штрихи существующих иконок сохраняются. `FlagIcon` — прежний SVG-флаг задачи, теперь единый для списков и задач. Без `color` он наследует нейтральный цвет; выбранному флагу передаётся его цвет. В кнопке задачи SVG сдвинут на 1 px влево для визуального центрирования. Кнопка только с иконкой обязана иметь `aria-label`; `title` его не заменяет.

Важная задача в строке списка использует тот же `StarIcon`, что кнопка создания. В строке иконка заполнена текущим цветом; в кнопке она заполняется и анимируется только после выбора.

## Геометрия и типографика

- `$spacing`: 4, 6, 8, 12, 16, 24, 32, 48 px. Для конкретного нового блока выбираем ближайшее существующее значение.
- `$radii`: 6, 7, 8, 10, 12 px и pill (999 px).
- Кнопки создания списка и задачи: 36 px высота, 8 px скругление. Панель задачи использует те же значения через `$task-control-height` и `$task-control-radius`.
- `$type-sizes`: caption, small, body, regular, heading. Системный стек шрифтов находится в `_base.scss`, line-height — 1.5.

```scss
@use 'sass:map';
@use 'variables' as v;

.example {
  padding: map.get(v.$spacing, 16);
  border-radius: map.get(v.$radii, 8);
  background: var(--workspace-surface);
  color: var(--workspace-text);
}
```

Не менять существующие отступы всего приложения ради выравнивания с новой шкалой. Эти значения — каталог уже применяемых решений.

## Анимации

| Название | Применение | Значение |
| --- | --- | --- |
| `list-options-in` | Появление панели | 180 ms ease; исходный эффект создания списка |
| Поворот PlusIcon | «+» → «×» | 180 ms ease, rotate(45deg), без scale |
| `task-option-slide-in` | Выкатывание параметров из «+» | `$motion-roll` (320 ms), `$ease-out`; задержки 0 / 45 / 90 ms |
| `task-star-pop` | Подтверждение выбора звезды | `$motion-star` (380 ms), `$ease-out`; краткий поворот и отскок |

Звезда анимируется только при выборе. Выкатывание не должно оставлять transform после завершения: используем `backwards`, чтобы hover продолжал работать. Не анимировать одновременно одну и ту же transform из нескольких правил. При `prefers-reduced-motion: reduce` движение отключается, состояние всё равно меняется. Календарь и выбор флага не должны сворачивать дополнительные параметры.

## Готовые React-блоки

```jsx
import { ListDatePicker, ListDeleteDialog, CustomSelect } from '../ui/index.js';
```

- `ListDatePicker`: управляемый календарь (`value`, `open`, `onOpenChange`, `onChange`), опционально дедлайн и повторение. Выбранная дата видна на кнопке как в создании списка. Проверяем поведение отдельно от каталога.
- При создании списка календарь показывает дату и быстрый выбор без действий «Повторять» и «Дедлайн». В задаче эти действия остаются. На десктопе меню флага и календарь задачи раскрываются вправо от своих кнопок.
- В создании задачи кнопки повторяют геометрию создания списка и сохраняют подпись «Аннотация». Все флаги используют один SVG; без выбора его цвет нейтральный. На десктопе флаг и календарь раскрываются у своих кнопок; на мобильном их панели занимают отдельный ряд. Срочность и локация остаются отдельными параметрами задачи.
- `ListDeleteDialog`: подтверждение с portal, удержанием фокуса и Escape. Передавать `id`, `title`, `confirmLabel`, `busy`, `theme`, `onClose`, `onConfirm`. Содержимое передаётся через children. Реальное удаление выполняет вызывающий код.
- `CustomSelect`: доступный выпадающий список (`id`, `label`, `value`, `options`, `onChange`, `disabled`), с клавиатурой и исходным стилем регистрации.
- `ListCard` / `ListTask` остаются в `workspace/Workspace.jsx`: это связанные с API блоки рабочего экрана. Каталог показывает их CSS-состояния, а не создаёт второй API-клиент.

## Тексты

`uiText.actions` — действия, `uiText.feedback` — ожидание и общие сообщения, `uiText.task` — подписи параметров. `taskUrgencyLevels` содержит действующие названия уровней срочности.

Кнопки: короткие глаголы («Сохранить», «Добавить»). Ожидание: «Сохраняем…», «Добавляем…». Не заменять подпись одного действия разными синонимами. Длинную техническую информацию не помещать в пользовательский интерфейс.
