# To Do Inn

Общайтесь с пользователем по-русски. Используйте английский для кода, имён файлов и сообщений коммитов. Сначала изучите затронутый код и тесты, затем внесите минимальные изменения, необходимые для задачи. Сообщайте о проверках и ограничениях.

## Архитектура

- Бэкенд работает на C#, ASP.NET Core и .NET 10 LTS. Интерфейс использует React, строгий TypeScript, Vite, Gulp и SCSS. Данные хранятся в PostgreSQL. Текущие границы и команды описаны в [архитектуре](docs/architecture.md).
- Размещайте C#-код в соответствующем предметном модуле и согласуйте пространство имён с каталогом. Оставляйте транспортный код в HTTP-адаптерах. Классы, которым нужны зависимости или которые используются несколькими точками входа, подключайте через DI ASP.NET Core. Добавляйте абстракции, когда они разделяют ответственность или упрощают проверку.
- Сохраняйте URL страниц и API, методы, статусы, JSON-поля, настройки регистрации и ограничения профиля. Суффикс `.php` используется существующими HTTP-контрактами ASP.NET Core.
- Сохраняйте порядок проверок CSRF и лимитов запросов, извлекайте ID и права из серверной сессии. Изменение или восстановление пароля отзывает прежние сеансы. Для PostgreSQL используйте параметризованные Npgsql-команды. При изменении записи сохраняйте транзакционные границы, проверки доступа и порядок блокировок.
- Миграции размещайте в `backend/Workspace.Api/Migrations/`. Существующий baseline сохраняйте как эталон, новые изменения оформляйте новой миграцией. Применяйте миграции явно. Сохраняйте действующие базы, содержимое, ID, хеши паролей, вложения и последовательности.

## Интерфейс

- Перед UI-изменениями прочитайте [библиотеку дизайна](docs/design-system.md) и используйте скилл `todo-inn-design`, если он доступен. Проверьте нужный компонент в реальном приложении и локальном каталоге.
- Переиспользуйте `frontend/js/ui/index.ts`, `icons.tsx`, `text.ts` и токены из `frontend/scss/_variables.scss`. Ищите точный компонент или состояние, которое указал пользователь.
- Сохраняйте обычное, hover, нажатое, выбранное, открытое, отключённое и фокусное состояния, обе темы, узкий экран и reduced motion. Для нового общего варианта обновляйте компонент, каталог и документацию вместе.
- В панели задачи неактивная звезда нейтральная, выбранная жёлтая с `task-star-pop`. Синяя кнопка «+» поворачивается на 45° без изменения размера и толщины. Выбранные дата и флаг оформляются одинаково, без точки. Дополнительные кнопки выдвигаются вправо с `task-option-slide-in` (0, 45, 90 мс), переносятся на узком экране и остаются раскрыты при выборе даты или флага.
- Редактируйте исходный SCSS. Каталог дизайна работает локально без API. Gulp пишет CSS в `frontend/css/`, Vite собирает сайт в `dist/`.

## Проверки и публикация

- Для запуска используйте Docker Compose или нативные `npm run dev:api` и `npm run dev` по [README](readme.md). Оба режима используют порт 5173 для сайта.
- Проверяйте TypeScript через `npm run typecheck`, интерфейс через `npm run test:frontend` и `npm run build`, сервер через `npm run test:local`. Серверный тест запускает временную PostgreSQL. Отдельно указывайте, если браузерную проверку не проводили.
- Секреты, ключи, локальные `.env`, дампы, сессии и личные рабочие материалы держите вне Git. Перед коммитом проверьте состав изменений. Коммит, пуш, деплой и изменения production выполняйте по явному запросу.
- Точно определяйте целевую PostgreSQL перед миграцией. Сохраняйте базы и серверный релиз для отката. Развёртывание через Caddy и systemd, изменения схемы и восстановление требуют отдельного согласованного шага.
